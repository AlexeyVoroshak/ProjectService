# Plan: Fix Database Creation and Kafka Connection

## Problem Summary
At startup:
- **Database is not created** — no data is persisted because `SaveChangesAsync` is never called
- **Kafka is not connecting** — `KafkaOutboxPublisher` background service fails silently

## Root Causes Identified

### 1. Critical: No `SaveChangesAsync` in any handler (DB not created)
**Files affected:**
- `ProjectService.Application/Features/Projects/Handlers/CreateProjectHandler.cs`
- `ProjectService.Application/Features/Projects/Handlers/UpdateProjectHandler.cs`
- `ProjectService.Application/Features/Projects/Handlers/DeleteProjectHandler.cs`
- `ProjectService.Application/Features/Tasks/Handlers/TaskHandlers.cs` (5 handlers)

All handlers call `_projectRepository.Add()` or modify entities, but **none call `SaveChangesAsync`**. The comment in `CreateProjectHandler` says "SaveChanges вызывается в ApplicationDBContext.SaveChangesAsync через pipeline behavior" — but the `DomainEventPublisherBehavior` only **adds** Outbox messages to `_dbContext.OutboxMessages`, it does **not** call `SaveChangesAsync`.

**Result:** DbContext tracks changes but never persists them.

### 2. Database initialization conflict in Program.cs
`EnsureCreatedAsync()` + `MigrateAsync()` are both called. `EnsureCreated` bypasses migrations entirely and creates tables directly. If migrations were applied, this causes duplicate table errors.

### 3. Kafka connection issues
`KafkaOutboxPublisher` creates a new `Producer` per batch (every 5s). If Kafka is unreachable, exceptions are logged but the background service may stop silently.

## Implementation Plan

### Step 1: Create a `SaveChangesPipelineBehavior`
**New file:** `ProjectService.Application/Behaviors/SaveChangesPipelineBehavior.cs`

Create a MediatR pipeline behavior that calls `SaveChangesAsync` **after** the handler executes, ensuring:
- Entity changes are persisted
- Outbox messages (added by `DomainEventPublisherBehavior`) are saved in the same transaction
- Both behaviors run in the same pipeline

The behavior must be registered **after** `DomainEventPublisherBehavior` in the pipeline so that Outbox messages are added before SaveChanges.

```csharp
public class SaveChangesPipelineBehavior<TRequest, TResponse> 
    : IPipelineBehavior<TRequest, TResponse>
    where TRequest : notnull
    where TResponse : notnull
{
    private readonly ApplicationDBContext _dbContext;

    public SaveChangesPipelineBehavior(ApplicationDBContext dbContext)
    {
        _dbContext = dbContext;
    }

    public async Task<TResponse> Handle(
        TRequest request,
        RequestHandlerDelegate<TResponse> next,
        CancellationToken cancellationToken)
    {
        var response = await next();
        await _dbContext.SaveChangesAsync(cancellationToken);
        return response;
    }
}
```

### Step 2: Register the new behavior in DependencyInjection
**File:** `ProjectService.Application/DependencyInjection.cs`

Register `SaveChangesPipelineBehavior` **after** `DomainEventPublisherBehavior`:

```csharp
cfg.AddBehavior(typeof(IPipelineBehavior<,>), typeof(DomainEventPublisherBehavior<,>));
cfg.AddBehavior(typeof(IPipelineBehavior<,>), typeof(SaveChangesPipelineBehavior<,>));
```

Pipeline order (inner to outer):
1. `DomainEventPublisherBehavior` — adds Outbox messages
2. `SaveChangesPipelineBehavior` — saves everything to DB

### Step 3: Fix database initialization in Program.cs
**File:** `ProjectService.API/Program.cs`

Replace the current DB initialization block:

```csharp
// BEFORE (lines 55-70)
var databaseCreated = await dbContext.Database.EnsureCreatedAsync();
if (app.Environment.IsDevelopment())
{
    await dbContext.Database.MigrateAsync();
}

// AFTER
if (app.Environment.IsDevelopment())
{
    await dbContext.Database.MigrateAsync();
}
else
{
    var canConnect = await dbContext.Database.CanConnectAsync();
    if (!canConnect)
    {
        throw new InvalidOperationException("Cannot connect to database");
    }
}
```

Remove `EnsureCreatedAsync()` entirely — use only `MigrateAsync()` which:
- Creates the database if it doesn't exist
- Applies all pending migrations

### Step 4: Improve KafkaOutboxPublisher resilience
**File:** `ProjectService.Infrastructure/Messaging/KafkaOutboxPublisher.cs`

Add try-catch around the entire execution loop so Kafka failures don't crash the background service:

```csharp
protected override async Task ExecuteAsync(CancellationToken stoppingToken)
{
    _logger.LogInformation("KafkaOutboxPublisher starting");
    
    while (!stoppingToken.IsCancellationRequested)
    {
        try
        {
            await ProcessPendingMessagesAsync(stoppingToken);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Error in KafkaOutboxPublisher processing cycle");
        }
        
        await Task.Delay(_options.PollIntervalMs, stoppingToken);
    }
    
    _logger.LogInformation("KafkaOutboxPublisher stopping");
}
```

Move producer creation to a singleton pattern (create once, reuse):

```csharp
private IProducer<string, string>? _producer;

private void EnsureProducer()
{
    if (_producer == null)
    {
        var producerConfig = new ProducerConfig
        {
            BootstrapServers = _options.BootstrapServers,
            Acks = Acks.All,
            RetryBackoffMs = 1000,
            MaxInFlightRequests = 1
        };
        _producer = new ProducerBuilder<string, string>(producerConfig).Build();
    }
}
```

## Verification Steps

1. **Start the application** — check logs for:
   - "База данных успешно создана" or migration applied
   - "KafkaOutboxPublisher starting"

2. **Create a project via API** (`POST /api/projects`):
   - Should return 201 with project data
   - Check PostgreSQL: `SELECT * FROM projects;` — row should exist

3. **Verify Outbox messages**:
   - `SELECT * FROM outboxmessages;` — should have entries with status 0 (Pending)

4. **Verify Kafka publishing**:
   - After 5 seconds, Outbox messages should change status to 1 (Published)
   - Check Kafka topic `project-service.events` for messages

5. **Test error recovery**:
   - Stop Kafka, create a project — should still work (data saved to DB)
   - Start Kafka — OutboxPublisher should publish pending messages
