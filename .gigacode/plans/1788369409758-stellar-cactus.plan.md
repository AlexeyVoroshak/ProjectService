# План реализации Redis кэширования

## Цель
Добавить кэширование данных в Redis для уменьшения нагрузки на базу данных и ускорения ответов API.

## Архитектура
- Кэширование будет реализовано на уровне Application layer (в query handlers)
- Используется библиотека `StackExchange.Redis`
- Кэш будет инвалидироваться при выполнении command operations (Create, Update, Delete)
- TTL по умолчанию: 5 минут для списков, 10 минут для отдельных сущностей

## Шаги реализации

### 1. Добавить зависимости
- Добавить `StackExchange.Redis` и `Microsoft.Extensions.Caching.StackExchangeRedis` в ProjectService.Application.csproj
- Добавить Redis сервис в docker-compose.yml
- Добавить connection string для Redis в appsettings.json

### 2. Создать сервис кэширования
- Интерфейс `ICacheService` в ProjectService.Application/Services/
- Реализация `RedisCacheService` в ProjectService.Application/Services/
- Методы: `GetAsync<T>`, `SetAsync<T>`, `RemoveAsync`, `RemoveByPattern`

### 3. Зарегистрировать кэш в DI
- Добавить регистрацию в `DependencyInjection.cs` (Application layer)
- Использовать опциональную конфигурацию (кэш отключен, если Redis недоступен)

### 4. Интегрировать в Query Handlers
- `GetProjectByIdHandler` — кэшировать по ключу `project:{id}`
- `GetAllProjectsHandler` — кэшировать по ключу `projects:all`
- `GetTaskByIdHandler` — кэшировать по ключу `task:{id}`
- `GetTasksByProjectHandler` — кэшировать по ключу `tasks:project:{projectId}`

### 5. Инвалидация кэша в Command Handlers
- `CreateProjectHandler` — очистить `projects:*`
- `UpdateProjectHandler` — очистить `project:{id}`, `projects:*`
- `DeleteProjectHandler` — очистить `project:{id}`, `projects:*`
- `CreateTaskHandler` — очистить `tasks:project:{projectId}`
- `UpdateTaskHandler` — очистить `task:{id}`, `tasks:project:{projectId}`
- `DeleteTaskHandler` — очистить `task:{id}`, `tasks:project:{projectId}`
- `UpdateTaskStatusCommand` — очистить `task:{id}`, `tasks:project:{projectId}`

## Ключи кэша
- `project:{guid}` — отдельный проект (TTL: 10 мин)
- `projects:all:{skip}:{take}` — список проектов с пагинацией (TTL: 5 мин)
- `task:{guid}` — отдельная задача (TTL: 10 мин)
- `tasks:project:{guid}` — задачи проекта (TTL: 5 мин)
