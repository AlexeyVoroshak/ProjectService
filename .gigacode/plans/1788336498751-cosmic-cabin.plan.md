# План реализации Unit of Work

## Контекст

Текущая архитектура использует `ApplicationDbContext` напрямую в репозиториях и pipeline behavior. `SaveChangesAsync` вызывается в `SaveChangesPipelineBehavior`, но нет единой абстракции Unit of Work для управления транзакциями и сохранением.

**Текущий поток:**
1. Контроллер → MediatR → Handler
2. Handler использует `IProjectRepository` (внедряет `ApplicationDbContext`)
3. `DomainEventPublisherBehavior` сохраняет события в Outbox
4. `SaveChangesPipelineBehavior` вызывает `_dbContext.SaveChangesAsync()`

**Цель:** Внедрить `IUnitOfWork` как единую точку для сохранения изменений и управления транзакциями.

## Шаги реализации

### Шаг 1: Создать `IUnitOfWork` в Domain layer

**Файл:** `ProjectService.Domain/Repositories/IUnitOfWork.cs`

```csharp
public interface IUnitOfWork : IDisposable
{
    DbSet<T> Set<T>() where T : class;
    Task<int> SaveChangesAsync(CancellationToken cancellationToken = default);
    Task<IDbContextTransaction> BeginTransactionAsync(CancellationToken cancellationToken = default);
    Task CommitAsync(CancellationToken cancellationToken = default);
    Task RollbackAsync();
}
```

### Шаг 2: Создать `UnitOfWork` в Infrastructure layer

**Файл:** `ProjectService.Infrastructure/UnitOfWork.cs`

```csharp
public class UnitOfWork : IUnitOfWork
{
    private readonly ApplicationDbContext _context;
    private IDbContextTransaction _transaction;

    public UnitOfWork(ApplicationDbContext context)
    {
        _context = context;
    }

    public DbSet<T> Set<T>() where T : class
        => _context.Set<T>();

    public async Task<int> SaveChangesAsync(CancellationToken cancellationToken = default)
        => await _context.SaveChangesAsync(cancellationToken);

    public async Task<IDbContextTransaction> BeginTransactionAsync(CancellationToken cancellationToken = default)
    {
        _transaction = await _context.Database.BeginTransactionAsync(cancellationToken);
        return _transaction;
    }

    public async Task CommitAsync(CancellationToken cancellationToken = default)
    {
        try
        {
            await _context.SaveChangesAsync(cancellationToken);
            await _transaction.CommitAsync(cancellationToken);
        }
        catch
        {
            await RollbackAsync();
            throw;
        }
    }

    public async Task RollbackAsync()
    {
        await _transaction.RollbackAsync();
    }

    public void Dispose()
    {
        _transaction?.Dispose();
        GC.SuppressFinalize(this);
    }
}
```

### Шаг 3: Обновить `ProjectRepository`

**Файл:** `ProjectService.Infrastructure/Repositories/ProjectRepository.cs`

- Заменить `ApplicationDbContext _context` на `IUnitOfWork _unitOfWork`
- Заменить `_context.Projects` на `_unitOfWork.Set<Project>()`
- Методы `Add/Update/Remove` остаются без изменений (работают через DbContext)

**Важно:** Репозитории не вызывают `SaveChangesAsync` — это делает pipeline behavior.

### Шаг 6: Обновить `DomainEventPublisherBehavior`

**Файл:** `ProjectService.Application/Behaviors/DomainEventPublisherBehavior.cs`

- Заменить `ApplicationDBContext _dbContext` на `IUnitOfWork _unitOfWork`

### Шаг 7: Обновить `DependencyInjection`

**Файл:** `ProjectService.Infrastructure/DependencyInjection.cs`

- Добавить регистрацию: `services.AddScoped<IUnitOfWork, UnitOfWork>();`
- **Оставить** регистрацию `ApplicationDbContext` (нужна для миграций в Program.cs)
- Обновить lifetime репозиториев с `AddTransient` на `AddScoped` (так как UnitOfWork scoped)

### Шаг 8: Обновить `Program.cs`

**Файл:** `ProjectService.API/Program.cs`

- Без изменений — `ApplicationDbContext` остаётся в DI для миграций
- UnitOfWork создаётся через scoped DbContext автоматически
