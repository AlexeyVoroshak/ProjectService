## Outbox Pattern Implementation

### Concept
Transactional Outbox — гарантия доставки доменных событий в Kafka путём записи событий в БД в той же транзакции, что и доменные операции. Background worker периодически публикует неподтверждённые сообщения.

### Flow
1. Command handler выполняет доменные операции + `SaveChanges()` (одна транзакция)
2. MediatR pipeline behavior перехватывает доменные события (`INotification`)
3. События сериализуются в `OutboxMessage` и сохраняются в БД
4. После коммита транзакции, `OutboxPublisher` (IHostedService) опрашивает `OutboxMessages`
5. Сообщения публикуются в Kafka, статус обновляется на `Published`
6. При ошибке — retry с exponential backoff, после N попыток → Dead Letter Queue

| Property | Type | Notes |

### Kafka Topics
- `project-service.events` — основная тема для событий
- `project-service.dlq` — dead letter queue для failed сообщений

### Retry Policy
- Max attempts: 5
- Backoff: exponential (1s, 2s, 4s, 8s, 16s)
- Batch size: 10 messages per poll
- Poll interval: 5 seconds
