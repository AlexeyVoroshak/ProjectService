# Plan: Fix ApplicationDBContext DI Registration

## Problem
`DomainEventPublisherBehavior<TRequest, TResponse>` requires `ApplicationDBContext` (abstract class from Application.Services), but only `ApplicationDbContext` (concrete class from Infrastructure.Data) is registered in DI. This causes MediatR to fail when activating the behavior.

## Root Cause
In `ProjectService.Infrastructure.DependencyInjection.cs`, only `ApplicationDbContext` is registered:
```csharp
services.AddDbContext<ApplicationDbContext>(options => ...);
```
But `ApplicationDBContext` (abstract base class) is never registered.

## Fix
Register `ApplicationDBContext` as an abstract type mapped to `ApplicationDbContext` in the Infrastructure DI registration.

### File: `ProjectService.Infrastructure/DependencyInjection.cs`
Add after the existing `AddDbContext<ApplicationDbContext>` call:
```csharp
services.AddScoped<ApplicationDBContext, ApplicationDbContext>();
```

This registers the abstract base class so that `DomainEventPublisherBehavior` can resolve it via DI.
